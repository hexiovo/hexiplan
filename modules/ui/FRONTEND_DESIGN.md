# Frontend Design · HexiPlan 适配版

参考：anthropics/skills / skills/frontend-design/SKILL.md。Apache-2.0；完整许可见 third_party/licenses。此适配将原有设计建议置于用户确认和低依赖约束之下，不是上游原文。

仅用于业务 UI 的新建/改版/原型，或用户明确批准的报告模板改版。普通报告内容填充不触发本文件，不擅自修改 HexiPlan 已有12套框架。

## 先提方案、后实施
以真实用户、任务、内容密度和环境为依据，提出合理且不重复的风格选择：信息结构、主流程、字体层级、颜色角色、间距、组件状态和交互说明。用户没有给真实数据时用明确标识的占位/模拟内容，不伪装实现或统计结果。

由 Astra 收集偏好并提交 UI 确认材料（现成 ui_review 模板可展示原型）。用户明确批准前，只做授权的比较稿/低成本原型，不实现其未确认的 UI 风格。原型批准也不代替 G4 当前步骤实施批准。

## 已获批后的实现
保持已确认风格和术语一致，围绕主要操作建立视觉层级。字体优先用户已有/系统字体，不私自下载或分发字体。配色和布局服务于任务，不用千篇一律的卡片/渐变/动画，也不为“独特”推翻用户喜欢的已有样式。

按钮说明具体动作，空状态说明下一步，错误说明原因与可行处理。照顾中文长度、窗口变化、键盘焦点、对比度和必要的降低动画设置。低性能设备减少特效和不必要刷新；未经许可不用桌面级鼠标控制。

浏览器需要时先由下层做真实权限与截图预检，最多2会话。完成后保存实际页面截图、操作路径和关键控制台日志，用现有截图总览/放大/对比界面呈现。区分设计稿、静态预览与实际运行截图。已存在正常功能不做无关重构；每项依赖、图标资源与第三方源码保持许可和来源记录。

局部自检和独立阶段校验沿用 HexiPlan，不增加反复美化循环。风格发生实质变化，先回 Astra 请用户确认。
