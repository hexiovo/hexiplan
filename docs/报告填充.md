# 报告填写：复用框架，不重写样式

## 最短路径
1. 只读取当前需要的 templates/json/<type>.json。
2. 复制到 RUN/plans/<用途>-vN.json，填写 meta 和 blocks。
3. Astra 内容由 Astra 决定；Sol-reporter 只排版、忠实组织材料，不代替制定路线。
4. 用固定程序渲染到全新版本目录：

```text
python HOME/tools/render_report.py --data RUN/plans/solution-v1.json --out RUN/reports/solution-v1 --asset-root RUN
```

5. 有人工批准关口时，交状态程序 submit，给用户完整 HTML 路径。对已经提交的页面禁止补写或覆盖，修订生成 v2。

## meta

```json
{
  "run_id": "实际任务ID",
  "gate": "solution",
  "step": "",
  "revision": 1,
  "date": "实际日期",
  "status": "待确认",
  "source_type": "PROJECT_DOCUMENT",
  "is_template": false
}
```

关口：requirements、solution、roadmap、step_plan、step_acceptance。非关口材料 gate 设空字符串。当前步骤的计划/验收必须填写实际 step ID；全局前三关 step 为空。

报告 type 与 gate 不完全同名：验收 type=acceptance、gate=step_acceptance。

roadmap 还需顶层 `roadmap_steps`：每项有 id、title、dependencies。step_plan 顶层 `work_packages` 同样包含 id、title、dependencies，并可添加 scope、acceptance、validation、owner 等。依赖必须在前面出现，不准预置某套固定项目步骤。

`blocking_questions` 必须为空才能提交确认；不是把尚未回答的关键问题藏在表格里继续推进。

revision 从状态 gate_versions 的当前 gate:step 记录加1获得。content_sha256 由渲染程序计算，不手填或手改。

## 共用内容块

- text/callout/code：text 字段；callout 可有 level（warning/danger）、title。
- kv：items，每项 label/value。
- metrics：items，每项 label/value。
- table：columns、rows；number、title、note、apa 可选；每行宽度一致。
- list：items 文本数组。
- timeline：items，每项 title、description、status。
- checklist：items，每项 text、status、detail。
- links/references：items；具体字段参照所选模板。
- gallery：images，每项 src、title、caption；caption 需注明“真实运行截图/设计草图/模板预览”。
- figure：src、title、caption、note。

简单斜体使用 `*p*`、`*M*`、`*SD*` 等；不用输入任意 HTML。所有文本会安全转义，不允许执行脚本。大段 Markdown 不会自动解释为完整排版，复杂内容拆分为规范块。

## 图片与截图

只嵌入 PNG/JPEG（不是改扩展名的 HTML/SVG）；src 相对于 JSON 文件，必须位于 --asset-root 指定范围。每张最多15MB。可保留高分辨率原始证据，并生成小图作报告展示以降低文件体积。

渲染后图片内嵌，双击 HTML 可离线看，也可进 Word。用 links 块指向实际日志/数据；这些外链不会打包进单个 HTML，发送时连同对应 evidence/logs 或最终交付包一起保留。敏感数据应脱敏截图并避免报告中嵌入不必要的个人信息。

## 模板选择

requirements：访谈总结；solution：技术路线与备选；roadmap：总步骤；step_plan：本步工作包；acceptance：本步验收；research：文献与方法；academic：APA风格结果；ui_review：候选界面；status：恢复与进度；guide：操作文档；change：重大变更/阻塞；delivery：最终摘要。

UI/方法子文档的批准应体现在当前 solution 或 step_plan 的决策记录里；不能把非关口模板当作绕过正式关口的捷径。

## 证据原则

不得填写虚构 PASS、截图、引用或统计结果。没有数据的学术框架保留待填，不编造数字。允许真实合成数据测试，必须声明其限定目的。报告代理使用执行代理的结构化输出，不再次手工重算或编造表格内容。需要附加图时由执行代理绘制并提供来源。

## 4.0 语言编辑保护

内容及证据确认后、render_report.py之前，由报告Sol选择report-style和对应Humanizer，学术报告再读academic-fidelity/scientific-writing。保留before/after JSON，用tools/guard_report.py检查受保护字段；通过后仍对照语义。已提交/批准内容保持不可变。选择记录与模块快照可由route_modules.py写入RUN，不能据此伪称已执行模型或已获用户批准。前端框架不修改。
