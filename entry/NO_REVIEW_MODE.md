# 默认无需审核：按推荐执行（对话适配 v1.15）

用户于2026-10-08明确设定“修正规则，最多三次反复修正，默认无需审核”。其中默认无需审核继续有效，旧固定次数已由2026-10-20的RETRY_POLICY.md覆盖。原文保存于entry/DEFAULT_REVIEW_AUTHORIZATION.txt。本规则仅在明确启用HexiPlan的任务中适用，不触发普通聊天的自动执行。

## 默认与覆盖

新任务没有相反的明确要求时，默认review_mode=recommended_execution。用户不必再说“无需审核”：需求、方案、推荐选择、步骤、改稿、补充和最终交付按推荐方案继续，不逐项等待回复。项目规模未指定就推荐并说明，已有决定保留。

用户在当前任务明确要求“恢复审核”“先让我确认”等，改为manual_review；后续说“无需审核”可改回。恢复同一任务沿用最近有效的明确选择；没有明确选择、只有旧系统默认时使用新默认，记录由来，不冒称用户新发了授权。新任务使用用户级默认，不自动继承上个任务的人工审核选择。

消耗档位与审核方式独立：常规由6.1 Sol-high规划/Luna-max优先执行，高消耗由Astra-high全部规划/Luna-max优先执行，超级消耗由Astra-high全部规划/6.1 Sol-high全部执行。无需审核不授权自动升档。

## 执行与限制

Astra开始梳理和收尾查漏保留，规划负责人说明推荐做法，由执行代理实施。小项目全轮完成后统一检验，较大项目按既定步骤；实际缺陷有实质进展就继续定向修复及必要复测，循环或卡死时停止并报告阻塞。未完成、失败或未验证不能算通过。

授权覆盖当前真实任务目标与必要补充，不扩为无关工作。鼠标接管仍须先申请；平台强制权限、用户专项限制和真正必需但缺失的资料不能靠推荐绕过。普通推荐选择不再询问，能独立进行的获准工作继续。

## 真实授权、报告与状态记录

1. 执行代理保存当前任务真实需求消息至RUN内，并复制上述默认授权原文至RUN/approvals的新文件；两者分开标明来源，不能伪装成当前用户新发的一条消息。note记录review_mode、authorization_source=user_default_policy、政策日期2026-10-08、原文路径、当前任务来源和范围。如用户在本任务另有明确授权或撤销消息，以该真实消息为准。
2. 状态命令统一使用HOME/entry/workflow_adapter.py；仍按原关口填充固定框架并submit，核对run/gate/step/revision与内容哈希。正文说明“按用户设定的默认无需审核规则采用推荐方案，用于说明和留档”，不必打开浏览器等用户阅读。
3. 对默认授权所覆盖且没有相反决定的推荐版本，使用workflow_adapter.py approve --user-message-file <真实默认授权原文或本任务授权文件> --map-content-sha256 <当前待处理报告哈希>。主Sol根据用户级规则、当前真实任务与规划负责人方案做明确映射，执行代理调用。另用note记录delegated_recommendation、授权来源、任务来源、推荐理由与报告哈希，不生成假确认令牌，不声称逐份人工审阅。只有默认授权文本而没有实际任务需求，不能批准业务。
4. 新版本逐次绑定实际哈希；replan以真实默认政策加当前任务/新增需求作为范围依据，记录原因，不伪造新用户指令。工具前置检查仍生效，失败或受阻不直接修改state.json绕过。原组件显示的通用“请确认”不撤销默认授权；正文说明当前模式即可，复用HTML/CSS/JS。
5. 恢复审核或暂停/取消时记录真实消息，后续不再用被撤销的授权推进，既有批准与历史保留。尝试与进展历史跨代理、补充和恢复保留，不因局部计划重置计数而绕过循环/卡死停止判断。

仅在任务明确限制某一步授权时按其范围执行；用户最新明确指令优先。无需审核不取消必要技术检验、不隐藏阻塞，也不改变鼠标接管申请或平台审批设置。

修复次数最新上限（v1.15）：最多30次，不要求用满；第30次仍失败就停止，不启动第31次。循环、卡死或无进展时仍提前停止。同一问题跨代理/档位/恢复/补充累计，不能重置计数绕过。详见RETRY_POLICY.md。
