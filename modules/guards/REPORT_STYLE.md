# Report Style · HexiPlan 文档与验收语言（本地定制）

仅对已授权报告内容生效。目标是便于用户做决定，不是让文本显得像某个人或通过检测器。正式、明确、具体；不虚构个人体验，不添加没有证据的优越性或性能宣传。

## 结构与事实
优先交代本页目的、需要用户决定的事项、实际成果、验证及限制。方案区分“建议/备选/待选”；过程区分“已实现/待实现”；验收区分“PASS/FAILED/NOT_RUN”。不写空泛开场、反复总结、自评分或“已完美解决”等无证据结论。

技术说明保留运行条件、步骤顺序和失败处理。学术正文使用 academic-fidelity；展示已有结果，而非为了凑 APA 样式增加检验。界面文案清楚说明动作后果，不靠广告词解释功能。保留必要列表和表格，不机械把一切改成长段或短句。

## 只改内容，不动框架
先选择 templates/json 中的模板。默认只改 text/callout 等叙述字段；标题、层级、表格、ID、路径、URL、状态、数字和元数据不能作为“去套话”目标。需要改标题或信息结构，属于另行明确的内容变更，不在本模块范围内。

不重写 templates/html、tools/report_assets、截图总览/放大/对比、DOCX 导出和确认按钮。原始日志、审批原话、第三方许可证及代码保持原文。

## 一次语言编辑
证据与初稿完整后，中文采用 humanizer-zh；英文采用 humanizer-en。没有表达问题的文字保持原样。不再安排单独润色代理，不逐模型反复加工，不输出草稿仪式/模板命中清单。

先保存初稿 JSON 到 RUN/plans，再保存润色稿到另一文件；均不能覆盖已登记的版本。下层执行：
```text
python HOME/tools/guard_report.py --before RUN/plans/before.json --after RUN/plans/after.json
```
检查不通过则停止渲染、对照恢复受保护内容。检查通过后再核对主张、条件和不确定性。此脚本不是统计或语义正确性的证明，也不是 AI 文本检测。

最后用已有 render_report.py 渲染并登记哈希。用户正在审阅或已批准的报告不可原地修改；需要修改时提交新版本。没有经过润色的初稿无需人为制造一轮改写，仅说明“无需语言修改”。
