# 工具准备、预算与恢复

执行者在准备阶段读取 extensions/TOOL_POLICY.md，先调查现有工具能力。仅计划新增时填写工具清单；原生浏览器/现成脚本满足任务时不强装MCP。

1. 将工具计划放入方案JSON的 `tool_plan`，并把全部关键字段转换为可见表格。截图用于证明预检，不证明安全。
2. 可运行 `python -B tools/check_tool_plan.py --plan PLAN.json` 做离线检查；不能把“检查通过”当成用户批准。
3. 用户明确批准该方案后，`--run RUN_DIR` 检查该清单是否确实出现在未篡改的审批报告里；不要代用户批准。
4. 经批准的安装脚本、虚拟环境、浏览器运行时放入 HOME/extensions 下专用目录，只用本次环境变量控制缓存。不升级系统Python/Node，不使用全局npm/pip，不持久写Codex配置。不能做到时先说明外部写入并确认。
5. 启用前验证实际Codex支持哪些会话级MCP字段，最小工具允许列表和运行时审批。不假设支持热加载；确需重启时先记录状态，等待用户启动专用会话，不在工具内部嵌套。
6. 两个浏览器用不同profile，或独立临时context；禁止挂接日常已登录会话。图片保存前检查敏感信息。
7. 每步记录工具版本、实际下载量、目录、所有者、依赖缓存引用、可重现命令、停止方法与日志摘要。仅清理确定无引用且登记的缓存；需要扩大原 tmp 清理范围时先明确授权。

模板中的空预算不是无限额度；使用者必须先写出实际可确认数值。不能为省空间删除仍需恢复的版本，也不能为了让检查通过编造下载大小或校验和。
