# 给 Codex 执行代理的状态/证据操作手册

Astra 只规划和指派，不直接执行下列命令。启动器由用户调用时初始化 RUN；之后由 Sol 记录/报告代理或获授权的执行代理操作。

下文 HOME、RUN 替换为绝对路径。命令要正确引用含空格/中文的路径。

## 状态与恢复
```text
python HOME/tools/workflow.py --run RUN status
python HOME/tools/workflow.py --run RUN recover
```

recover 从最新 journal 恢复快照，不改变批准。若最新已提交 journal 损坏，停止并报告；不要静默回滚到旧授权。若 .state.lock 遗留，先确认没有存活写入进程，再在本次授权范围内修复，禁止自动抢锁。

## 提交和记录批准
```text
python HOME/tools/workflow.py --run RUN submit --gate solution --report reports/solution-v1
python HOME/tools/workflow.py --run RUN approve --user-message-file RUN/approvals/user-message.txt
```

user-message.txt 必须是用户实际提交的原文，不能由代理自行写一份假批准。默认要求原文包含 HTML 页上的完整确认文本。

若用户实际说了明确无歧义的自然语言批准，记录代理可将这条原文显式映射到唯一待批哈希：
```text
python HOME/tools/workflow.py --run RUN approve --user-message-file RUN/approvals/user-message.txt --map-content-sha256 当前待批完整哈希
```

映射不是自动语言判断或身份认证；只能依据真实用户消息，不能接受“可能可以吧”、未回答或工具自造确认。不能把旧批准套用给新报告。

退回修改：
```text
python HOME/tools/workflow.py --run RUN reject --reason 用户实际提出的修改要求
```

## 当前步骤执行
step_plan 已批准且 phase=execution/repair 后才可记录实现结果。
```text
python HOME/tools/workflow.py --run RUN package-result --package 实际工作包ID --status PASS --evidence evidence/该工作包结果.json
python HOME/tools/workflow.py --run RUN verify-start
```

记录 evidence 为 RUN 内实际文件，不能仅回复“完成”。PASS 指该包已达到局部要求，不代替独立整合校验。

## 独立校验与最多两轮修复
独立 Sol 输出结构：
```json
{
  "overall": "PASS",
  "independent_reviewer": "实际独立Sol代理ID",
  "criteria": [
    {"id": "实际验收项ID", "status": "PASS", "required": true,
     "evidence": "实际命令、输出记录或证据位置，并说明验证范围"}
  ],
  "source_type": "ACTUAL_EXECUTION",
  "limitations": []
}
```

这是字段说明，不是现成测试结果；必须用真实执行证据替换。
```text
python HOME/tools/workflow.py --run RUN verdict --evidence evidence/verification-v1.json
```

必要项 FAIL/BLOCKED/NOT_RUN 不允许 overall=PASS。NOT_APPLICABLE 必须说明依据，不能偷换为“未测”。FAIL 后第一次进入 repair_rounds=1；复测失败进入2；第三次仍FAIL进入blocked。两轮是修复轮次，不含初次校验。不同模型/代理不能重置这一步的计数。

## 资源账本
```text
python HOME/tools/workflow.py --run RUN lease-acquire --owner 代理ID --kinds sol
python HOME/tools/workflow.py --run RUN lease-acquire --owner 代理ID --kinds luna,browser
python HOME/tools/workflow.py --run RUN lease-acquire --owner 代理ID --kinds high_memory
python HOME/tools/workflow.py --run RUN lease-release --owner 代理ID
```

角色对应Sol3/Luna6全任务共用；browser2/high_memory1。资源按“实际运行的代理/会话/任务”计数；一个代理持有两个浏览器会话时用不同会话owner分别登记，不因一个owner有browser标记就开任意数量。

等待下层结果但仍存活的Sol管理代理仍占Sol名额。不同用途的Sol共用3个名额，需要时关闭/暂停并保存摘要后再启动校验或报告代理，不留常驻记录进程。首次Sol记录代理可先登记自己，再登记其他owner；代理结束前登记释放。恢复时核对真实存活对象，不盲目清空账本。

本账本是合作式调度，不是OS强制进程隔离。实际spawn权限与Codex线程限制优先。主线程按原生限制最多9个子线程，不能把此值解释为3Sol+6Luna一定都需开满。

## 清理
```text
python HOME/tools/workflow.py --run RUN temp-add --path tmp/实际临时文件
python HOME/tools/workflow.py --run RUN cleanup
python HOME/tools/workflow.py --run RUN cleanup --apply
```

只登记已存在的 RUN/tmp 普通文件。--apply 只在校验通过后的report阶段使用。自动保留内容已变更或被报告/证据/计划引用的文件。未登记的文件不删。不递归删目录、不跟随链接、不清全局缓存。零删除也记日志，然后才能提交本步验收。

## 暂停和获批重规划
```text
python HOME/tools/workflow.py --run RUN pause --reason 实际原因
python HOME/tools/workflow.py --run RUN resume-phase
python HOME/tools/workflow.py --run RUN replan --gate step_plan --user-message-file RUN/approvals/实际用户重规划指示.txt --reason 方案需要改变的实际原因
```

replan 只返回 solution 或当前 step_plan 的起草阶段，不批准新方案，不立即清空修复计数。新 HTML 经用户确认才产生新执行授权。保留原状态、失败记录和批准历史。先停下相关执行者再重规划，不能同时依据两版计划写入。

重要路线/范围/UI变更使用solution；仅当前步骤重分解可用step_plan。不要为了绕过两轮修复上限而机械生成同一份“新计划”。

## 最小合成验证数据
```text
python HOME/tools/generate_fixture.py --out RUN/fixtures/synthetic-tabular-v1 --kind tabular
python HOME/tools/generate_fixture.py --out RUN/fixtures/synthetic-signal-v1 --kind timeseries
```

生成实际CSV与来源/种子/已知答案清单。这些只是通用软件测试夹具，不预设用户任务应采用的分析参数。实际项目需要的更专门夹具由执行代理设计，保留生成代码和对照依据。不得混入真实被试数据或用于声称实证结论。

## 4.0 模块选择记录

下层可执行：
```text
python HOME/tools/route_modules.py --role sol-reporter --kind report --language zh --run RUN --owner AGENT_ID --record-selection
```
记录只保存在该run内；参考副本位于 references/module-snapshots，状态journal保存模块ID、哈希及本次选择。状态摘要新增module_selections；任何确认关口、资源和重试计数不因此改变。选择不等于已阅读/已执行，更不等于用户批准。恢复时只读取当前任务所需的已记录模块副本，版本冲突请Astra处理，不悄悄更新。


## 5.1 意见记录

`review_feedback.py --report ... --feedback ...` 默认只验证，配合 `--record --run RUN --user-message-file ...` 才记录到 RUN/feedback 与 journal。实际用户消息必需；不推进状态。`workflow.py status` 和恢复摘要新增 `latest_feedback`，沿用原报告版本。
