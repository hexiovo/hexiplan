# 使用说明

## 1. 放在哪里

把整个 HexiPlan 文件夹放在你选择的新空目录。部署不会自动修改现有全局/项目配置、AGENTS.md、Skills、PATH、默认模型，也不覆盖旧 HexiPlan。

三个路径的含义：
- HOME：本工具包根目录；协议、角色、模板、程序和运行记录都在这里。
- PROJECT：用户另行指定并授权的业务项目目录。
- RUN：HOME/runs/<任务ID>；计划、状态、审批、报告、截图、日志、合成验证数据和临时文件在这里。

业务实现只有在当前步骤批准后才修改 PROJECT。源码/结果最终交付目录由该任务确认，不由安装过程擅自设定。Codex 自身通常仍有正常会话记录、缓存和已有项目规则；本包不会删除、禁用这些机制，也不承诺操作系统零写入。

## 2. 最省力的使用

Windows 双击 `start-hexiplan.cmd`。

新任务：选择“新建”，填写业务项目路径，随后在 Codex 中输入所有需求。Astra-high 会先理解和提问，不直接实现。

继续任务：再次双击，选择未完成任务。状态从 journal 恢复，不把重新打开当作你的批准。

也可以在已有终端显式调用：

```powershell
& "你的HexiPlan路径\start-hexiplan.ps1" -ProjectPath "你的项目路径"
```

或直接使用 Python：

```text
python "你的HexiPlan路径/tools/launch.py" --project "你的项目路径"
python "你的HexiPlan路径/tools/launch.py" --resume
python "你的HexiPlan路径/tools/launch.py" --run-id "实际任务ID"
```

本包没有注册 `$hexiplan` 全局命令，也不向日常 Codex 自动注入协议。普通会话继续使用你自己选的模型。读取 hexiplan.md 本身不能改变已经运行的模型或保证角色配置被加载；要获得这套真实模型路由，优先使用独立启动器。不要在一个 Codex 工具调用内部再启动交互式 Codex；安装完成后由你双击启动。

## 3. 本机前提与预检

需要已有 Python 3.10+ 和可以工作的 Codex CLI。启动器不自动安装任何软件。

```text
python tools/verify_package.py
python tools/launch.py --project "实际项目目录" --check-only
```

check-only 只检查现有 CLI/角色文件并打印本次会话参数，不调用模型，不创建业务任务，不证明账户已能访问三个模型。

首次正式启动后，下层代理应确认角色、模型、推理档位及权限。模型/档位不受支持时必须明确报告并停止相关执行，不静默换模型。模型预检使用最小任务即可，不安排庞大重复测试。

本次专用会话临时请求 PROJECT、RUN 和 HOME/extensions 的写权限；实际工具安装仍必须先批准清单。Astra 不执行属于角色行为约束，不是假装进程有“只读父代理却可写孙代理”的权限隔离。平台、安全策略和你的真实授权优先；禁止 yolo/关闭审批/永久修改配置。

## 4. 你如何确认

每次审阅报告时，打开对应 `report.html`。

最稳妥：点击“复制确认文本”，粘回 Codex。文本含任务、关口、步骤、版本和内容哈希，只批准这一页。

你也可在对话中明确说“确认当前 v2 方案”，但必须只有唯一可对应的待批版本；记录代理保存你的原话并显式绑定其内容哈希。有歧义应追问，不能从沉默、打开页面、下载文件或代理点击按钮推断批准。

页面上的备注只保存在该浏览器本地或导出的反馈 JSON；页面不连接 Codex、不会直接写运行状态。反馈文件只是材料，不是自动批准。提交后的报告不可改写；修改则创建新版本，并重新确认。

## 5. HTML 框架的使用

12 套框架覆盖需求、正式方案、整体步骤、当前步骤计划、验收、研究方法、学术结果、UI评审、恢复状态、说明书、变更、最终交付。

后续代理复制相应 JSON 到 RUN/plans，只填写内容，调用固定渲染器。不重复生成 HTML/CSS/JS，不全文反复读取所有模板。所有页面离线可看，无外部字体、CDN、追踪或远端图片。

截图有总览缩略图、点击放大、选择两张并排比较。原始截图保留于 evidence；报告可嵌入缩小后的展示副本，二者要注明关系。模板自身的截图明确是模板预览，不是业务程序执行证据。

## 6. Word / DOC 导出

点击 HTML 顶栏的“导出 Word”：在浏览器本地生成真正的 OOXML `.docx`，包括正文、表格和嵌入图片，不需要安装 JS 依赖，也不是 HTML 改后缀。

确实需要 Word 97–2003 `.doc` 时，先导出 `.docx`，在已安装 Microsoft Word 的 Windows 中执行：

```powershell
& "你的HexiPlan路径\tools\export-doc.ps1" -InputDocx "报告.docx" -OutputDoc "报告.doc"
```

也可用 Word 的“另存为”选择 Word 97–2003 格式。未安装 Word 时仍可使用 `.docx`；本包不为转换自动安装 Office。不覆盖已有输出文件。旧格式可能有功能或排版差异，转换后应看一遍。

APA 框架提供结果段、三线表、图题/表注位置；具体统计报告要匹配分析与期刊要求，不能把套用模板等同于已满足所有 APA 规范。

## 7. 浏览器与验证

早期实际检查可用的浏览器自动化工具及截图/日志能力，尽早触发必要权限。优先独立会话，不控制整台电脑或登录你的个人浏览器。前置授权不等于以后绝不再请求权限。

可生成实际合成验证数据文件，并下载必要公开资料/基准；必须标明 SYNTHETIC_ONLY/PUBLIC_BENCHMARK 等来源、用途和限制。不得改生产参数迎合测试，不将模拟通过写成真实研究验证。缺少条件时尽可能验证可验证的部分，剩余准确标为 NOT_RUN/BLOCKED。

## 8. 恢复、清理与资源上限

版本化 journal 是恢复依据，state.json 是可重建快照。可以移动整个 HOME，但不要重命名单个 RUN；PROJECT 搬迁需要明确核对，不能静默指向另一路径。

关闭的代理/浏览器要释放协作资源记录。该账本不是操作系统级进程限制；若代理绕过它，它不能拦截系统行为。主线程的原生子代理上限也不区分模型或浏览器类型。

只清理本次登记的 RUN/tmp 内普通文件，检查内容未改变且未被保留材料引用。目录外、原始数据、审批、结果、证据、许可证与必要复现条件不清理。每步保留清理日志，即便删除数量为0。

修复最多两轮。仍阻塞时停下来；需要重规划则保留失败记录，经用户明确同意新方案/步骤后再推进，不通过重启或换代理清零重试。

## 9. 实机限制

包内包含本地程序/HTML/Word导出的验证记录。没有替你在 Windows、登录账户、项目数据和实际模型服务中执行安装或三模型联调。请以首次实际预检结果为准。

## 4.0 新增模块

不改变使用入口。modules/是普通本地规则目录，不是Skill安装位置；modules/MODULE_ROUTER.md按工作内容分派。报告Sol负责一次中文/英文润色，科研/UI/调试模块按需调用。详见 docs/模块与省上下文.md（从工具包根目录定位）和 MODULES.html。

升级使用新的空目录；旧任务继续从旧入口恢复，不自动合并记录。安装阶段不联网安装任何上游项目。真实模型/权限不足时停止，不静默换模型。

## 5.0结构化页面
先打开 UI_OPTIONS.html 选择结构。全部淡绿色；正式报告在用户确认的结构上用 tools/render_layout.py 填充，不重复生成页面代码。查看 docs/5.0更新说明.md。工具策略看 extensions/TOOL_POLICY.md，具体工具默认未授权。


## 5.1 逐项反馈

见 `针对性反馈.md`。入口 `REVIEW_DEMO.html`，导出JSON交给Codex即可定位。默认不修改旧报告；本地草稿不等于已提交，导入意见也不等于批准。
